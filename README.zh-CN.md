# dsh-panellist

DSH（DeepSeek Harness）客户端「面板列表」的管理插件。

面板列表（panellist）是会话界面左侧那一列由各个插件贡献的全局入口——插件、自动化任务、技能中心、记忆系统、SSH、MCP 连接器……它们来自不同的插件，顺序由各自声明，图标与名称也由各自决定。

本插件让**用户**接管这件事：哪些页签出现在轨道上、以什么顺序出现、叫什么名字、用什么图标，以及把若干页签收进一个分组。所有配置都在「设置」里的一项新页签内完成，改动即时生效。

> 状态：**已实现**（里程碑 2–5 完成，里程碑 6 部分完成）。本文是双方确认过的行为规范；实现取舍记录在 [docs/adr/0001](docs/adr/0001-registry-rewrite-plus-minimal-dom.md)，技术细节在 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)，配置格式在 [docs/config.schema.json](docs/config.schema.json)。术语定义见 [GLOSSARY.md](GLOSSARY.md)。
>
> 与最初设计的三处细化（都是实现期间发现的，已回填本文）：分组的轨道 id 是 `dsh-panellist:<groupId>`；未配置页签始终列在整条轨道里，但只有序列非空（即你做过结构性改动）时才写 `order`；`/panellist/api/reveal` 这个端点是为了实现「打开配置文件」而新增的。

## 1. 为什么需要它

DSH 的面板列表是**只读投影**：外壳枚举 `sidebar.panellist` 槽位里的注册项，按每一项**注册时自报的**顺序排序渲染。官方没有提供任何改写他人注册的 API：

- 顺序只读——插件只能决定自己那一项的 `order`；
- 没有「分组」概念——一行就是一个页签；
- 图标由贡献者提供的组件决定，名称由贡献者的 `label` 决定；
- 「设置」导航页签的图标只能从内核内置的一份清单里挑。

因此本插件必须同时用两个杠杆，并且把 DOM 介入压到最小：

1. **注册表改写**——在运行时改写注册项上的顺序、名称与图标组件（注册项对象未被冻结，改写在运行时实测有效）；本插件的改动不触碰任何插件的页面本身。
2. **最小 DOM/CSS 重投影**——只有一件事无法靠注册表完成：把某一行从轨道上「拿掉」。分组行本身也是注册项（由本插件注册），因此它的行框、高亮、提示与收起态行为依旧由外壳负责；弹出菜单是覆盖层，不改动原生行。

这条路径的取舍与代价记录在 [ADR-0001](docs/adr/0001-registry-rewrite-plus-minimal-dom.md)。

## 2. 行为规范（已确认）

### 2.1 管理对象

- 面板列表里的**所有**注册项一视同仁：内核自带项（插件、自动化任务、技能中心、记忆系统、SSH、MCP 连接器）与第三方插件注册的项都可被管理。
- 本插件自己的设置页签不在面板列表内，因此不参与管理。
- 真实页签 id 在运行时发现，不硬编码；本文档示例里的 id 仅是示意。

### 2.2 序列模型

轨道序列是一串**有序项**，每一项要么是**单个页签**，要么是一个**分组**：

- 每个页签在整条序列中**恰好出现一次**（序列是对页签集合的划分，不重复）；
- 分组自身占据序列里的一个位置，并含有一个**有序的**页签子集；
- **只允许一层**嵌套（分组内不能再放分组）；
- 空分组非法；只含 1 项的允许，但管理面板会提示。

你给的六个例子按此模型解释如下（`G{…}` = 一个分组）：

| 你的写法 | 解释 |
| --- | --- |
| `a c b d e` | `[a][c][b][d][e]` |
| `a b c` | `[a][b][c]` |
| `a 下拉（b c d e）` | `[a][G{b,c,d,e}]` |
| `a 下拉（b d e c）` | `[a][G{b,d,e,c}]` |
| `a 下拉（b e c）d` | `[a][G{b,e,c}][d]` |
| `下拉（a b c）d e` | `[G{a,b,c}][d][e]` |

### 2.3 显示 / 隐藏

- 只有两态：**显示** / **隐藏**（没有「禁用」第三态）。
- 隐藏 = 不再出现在轨道上，但页签本身依然存在、依然可用（可从管理面板选中、可被其它插件或快捷键激活），它所属插件的功能不受影响。
- 例外：**被隐藏的页签若正处于激活态，它那一行临时显示**——避免出现「人还在这个页面，轨道上却没有入口」。

### 2.4 名称覆盖

- 纯显示层覆盖，只影响三处：轨道行的文字、收起状态的提示文字、无障碍名称。
- 不改动 DSH 其它位置（设置、命令面板等）中的同名显示，也不改变贡献者声明的原始名称。
- 首版为**单字符串**，对所有语言生效。

### 2.5 图标覆盖

三种来源，可随时切回原图标：

1. **保留原图标**（默认）；
2. **内置图标集**——本插件自带的一小组内联矢量图标（零依赖，24 个通用图形），离线可用。它们按 **DSH 自己的图标规范**绘制——即 `@deepseek-ai/dsh-client-ui-primitives` 那套产品图标所用的画布、线宽与构图：`viewBox="0 0 16 16"`、`fill="none"`、`stroke="currentColor"`，线宽取 **Medium 1.3**（`Icon*OutlineMedium`，也就是轨道行与设置导航已经在用的那一档）、几何落在 16 网格的半像素坐标上并与边缘留 1 个单位、圆头圆角、`aria-hidden`、无 id 与外部引用。设置页签自己那颗图标就是这套里的 `list`，以 `currentColor` 蒙版画在外壳原本的兜底齿轮位置；
3. **用户上传图标**——粘贴 SVG 源码；
   - 白名单净化：移除 `script`、`foreignObject`、事件属性、外部引用（`href`/`xlink:href` 指向外部的用例）；
   - 单个 SVG 上限 **64 KB**；
   - 内联渲染（不是 `<img>`），因此能随主题变色。

### 2.6 分组与组头

- 组头有**独立**的图标与名称，默认预填「组内第一项」的图标与名称（常用名如「更多」），用户可改。
- 组头**整行可点**，点击即展开分组菜单；整行点击一律用于展开菜单，不会跳转页面。菜单里只列该分组的成员：标题行里原本还有一个指向分组自己那一页的「概览」入口，已按用户反馈删除。那一页仍保留为分组 `main` 的兜底页（这样程序化选中分组 id 时不会报错），但不再有任何自己的入口。
- 组内任一项处于激活态时，**组头高亮**，用户不展开菜单也能看出当前页面在哪个组里。
- 拖拽新建分组时，分组插到**「最靠上的那个成员」原来的位置**，即分组「长在」它成员的原地。这条规则由模型保证（`createGroup` 以「最靠上成员上方那一行」的身份为锚点），因此与具体手势无关。

### 2.7 分组菜单

- **点击展开**（悬停不展开，避免误触）。
- 键盘可达：`Enter`/`Space` 展开、`Esc` 关闭、上下方向键在组内移动。
- 侧栏收起成 56 px 轨道时，菜单一律**向右弹出**（flyout）。
- 组内项数超过可视高度时菜单可滚动；首版**不做**组内搜索框。

### 2.8 未配置项与孤儿

- 新装的插件注册了一个你还没动过的页签 → 它**直接出现在序列里**（在已配置项之后，按它自身的顺序），不需要先「纳入」它。
- 某个页签的贡献者被卸载、而配置里还留着它 → 配置**保留**，管理面板标注「已缺失」，并提供「清理孤儿」按钮。
- 在你**做结构性改动之前**（拖动、建组/解散分组），本插件**不写任何顺序**：轨道保持贡献者自己的顺序。改名、换图标、隐藏只覆盖那一项、不动顺序——这正是「不碰你没让我碰的东西」的落点。

### 2.9 生效方式

配置改动**即时生效**：不需要重启 DSH，不需要重载任何插件，也不需要重新加载页面。这对**每一次**改动都成立，包括那些「什么都不用写」的改动：改写环节会比较一份「轨道渲染所依赖的一切」（顺序、名称、图标、显示/隐藏）的摘要，只要它变了就重新投影——所以第二次换图标、第二次改名，和第一次一样立刻上轨道（ARCHITECTURE §4.5）。

### 2.10 接管范围

管理面板里**从第一次打开起就列出整条轨道**：不需要先把某个页签「纳入」才能碰它，也不存在一份「还没接管」的清单。（中途曾有过「未配置清单 + 逐项接管 / 恢复原生」的设计，已按用户反馈删除——它们只是让人多点一步。）

真正仍然成立的「最小干预」性质落在**写入**上，而不是界面上：

- 配置里的 `sequence` 是**部分权威**：只记你实际改过的东西。
- `sequence` 为空时**不写任何 `order`**（新装即如此，纯 no-op），未配置项的名字/图标/隐藏一概不碰；它们保持贡献者自己的顺序。
- 你第一次做结构性改动（拖动、合并分组）时，当前顺序会被写成显式序列；此后未配置项仍按各自的原生顺序列在已配置块之后（README §2.8）。

实现见 `src/shared/model.ts`：`rows` 永远是整条轨道（未配置的行 `order` 为 `null`，即「不改」），而 `reordering` 决定是否真的写 `order`。

## 3. 设置页签

在「设置」对话框左侧新增一项：

- 名称：**面板列表**；位置：排在设置导航靠后；
- 图标：用生态同款标记法把这一行的字体图标换成本插件自己的图标；探测失败则退回内核原生齿轮图标（不报错）。

页面内容：

1. **序列编辑器**——列出整条轨道（从一开始就是全部页签，无需先「纳入」）。主通道是**拖拽**（排序、拖入已有分组、把成员拖出分组），新建分组用每行的「与下一项合并为分组」按钮，解散分组用「解散分组」；键盘兜底是每项的**上移/下移**；每行还有**「隐藏」/「显示」**按钮，就地切换这一行的可见性（分组行同样适用）。「还没配置任何东西」这件事刻意不显示：列表本身就是轨道，第一次拖动或建组时才会把顺序写成显式序列——上方没有说明横幅，也没有「以当前轨道顺序作为起点」这一步；
2. **项的外观覆盖**——名称、图标（保留原图标 / 内置图标集 / 粘贴 SVG），点该行名字即可打开——**分组内的成员同样可以**（它们没有自己的顶层行，否则根本点不到）；显示或隐藏由序列列表每行的**「隐藏」/「显示」**按钮负责（单一入口，不在两处重复）；
3. **分组编辑**——组头名称、组头图标、成员顺序；
4. **配置导入 / 导出**（JSON）；
5. **打开配置文件**——直接打开 `$DSH_HOME/panellist.json`；
6. **清理孤儿**；
7. **自检状态**——显示四项自检结果与「重新自检」按钮（见第 5 节）。

## 4. 配置与接口（草案）

### 4.1 存放位置与作用域

- 文件：`$DSH_HOME/panellist.json`（权限 `0600`，写入为「临时文件 + 原子重命名」，Windows 文件锁冲突时回退直写）；
- 作用域：**按 profile 分开**存于同一份文件内，因为不同 profile 安装的插件不同；
- 迁移：配置带 `schemaVersion`，读到旧版本按需迁移；
- 损坏：解析失败时**备份原文件**并回退默认值，不静默丢弃用户手改过的内容。

### 4.2 配置形状（示意）

```json
{
  "schemaVersion": 2,
  "profiles": {
    "desktop": {
      "sequence": [
        { "type": "entry", "id": "plugins" },
        {
          "type": "group",
          "id": "group:work",
          "label": "更多",
          "icon": { "kind": "original" },
          "members": ["schedules", "skills", "memory"]
        },
        { "type": "entry", "id": "ssh" }
      ],
      "entries": {
        "plugins": { "label": "插件市场", "icon": { "kind": "builtin", "name": "puzzle" } },
        "mcp-connector": { "hidden": true }
      },
      "meta": { "updatedAt": "2026-10-10T03:00:00.000Z" }
    }
  }
}
```

权威定义见 [docs/config.schema.json](docs/config.schema.json)。`sequence` 是**部分**权威：列出的项按此顺序，未列出的项由程序追加到末尾。

### 4.3 本插件占用的接口

| 用途 | 标识 |
| --- | --- |
| 设置导航页签 | `settings.section` id = `dsh-panellist` |
| 分组行（轨道） | `sidebar.panellist` id = `dsh-panellist:<groupId>`，例如 `dsh-panellist:group:work` |
| 分组概览页（中心栏兜底页，防止选中调用报错） | `main` key = 同上 |
| 宿主半本机路由 | `/panellist/api` |

宿主半路由（仅本机回环可达，带 trusted-host 栅栏）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/panellist/api/config?profile=<id>` | 读取该 profile 的配置 |
| `PUT` | `/panellist/api/config?profile=<id>` | 整体写入（服务端校验 + 原子落盘） |
| `POST` | `/panellist/api/config/reset?profile=<id>` | 回退默认 |
| `POST` | `/panellist/api/reveal` | 在系统文件管理器中定位配置文件（「打开配置文件」按钮） |
| `GET` | `/panellist/api/health` | 配置存储与字段级自检状态 |

`?profile=` 只接受 `$DSH_HOME/profiles/<id>` 真实存在的 id；不带该参数时写入宿主自己的 profile（`DSH_PROFILE`）。`/health` 与 `/reveal` 是整份文件级别的，忽略该参数。

两个半边的导出契约（与生态一致）：

- 宿主半：`name`、`inject`、`apply(ctx, config?)`
- 浏览器半：`apply(ctx)`、`inject`
- 清单：`dsh.bundle.patch`（自动挂载）+ `dsh.client.{inject,platform}`

## 5. 兼容性、自检与降级

**版本门槛**：`engines.dsh: ">=0.2.0-rc.2 <0.3.0-0"`（与开发所用的内核版本一致；类型包在 npm 上同版本可取，因此编译期就能发现契约漂移）。

本插件依赖 DSH 的四条**内部**事实（都不是公开契约），因此启动时逐项自检：

| 依赖的内部事实 | 失效后的后果 | 探测方式（`src/client/rail/probe.ts`） | 降级 |
| --- | --- | --- | --- |
| 槽位注册项对象未被冻结，可事后改写 `order`/`label`/图标组件 | 顺序、名称、图标改不动 | 临时注册一个探针行，改写它的 `order` 再通过 `entriesOfSlot` 回读；同时检查对象与 `options` 都未被冻结 | 停用改写，只读 |
| 轨道行的 DOM 结构可被定位，且 CSS 支持 `:has()` 选择器 | 「隐藏」这一项无法生效 | `CSS.supports('selector(:has(*))')`，并用**与隐藏规则完全相同**的选择器数行数，与 rail 注册项数比对（轨道未挂载时记为通过并写明原因） | 停用隐藏（其余改写保留），只读提示 |
| 外壳仍把「是否激活」传给图标组件（隐藏中的激活页签需要它） | 隐藏中的激活页签无法临时显示 | 临时注册一个探针行，等两帧确认它的图标组件确实被渲染、且收到的 `active` 是布尔值 | 该规则失效：隐藏变为无条件隐藏 |
| 设置导航按钮可由可见文本定位 | 设置页签图标换不了 | 对话框打开时按文本匹配自己的行；未打开时记为通过并写明（标记由 `MutationObserver` 在每次打开时重跑） | 保留原生齿轮图标 |

- 任一项自检失败 → **降级为只读**：不再做任何改写，管理面板顶部给出明确提示（哪一项失败、影响什么、如何反馈），并保留「重新自检」按钮。
- 绝不静默半坏，也不阻止插件加载（DSH 升级后界面仍然可用）。
- 已知不确定性：DSH 的样式类名是**构建哈希**，会在发版时重掷。因此选择器一律使用「稳定后缀」匹配（例如 `[class*="_panelRow"]`，实测有效；`[class$="_panelRow"]` 在激活行上会失败），并且每次挂载都重新探测一次。

## 6. 安装与开发

### 用户安装（发布后）

```bash
dsh plugin --profile desktop add dsh-panellist
```

包的清单里声明了自动挂载层，因此不需要手改 profile 配置。

### 本机开发（当前阶段）

```bash
# 在本仓库根目录
pnpm install
pnpm build

# 把本仓库以 link 方式挂进 desktop profile（DSH 需先完全退出）
dsh plugin --profile desktop add link:E:/ai-code-space/dsh-panellist

# 开发循环
pnpm watch      # tsdown --watch，重新构建浏览器半，由客户端 HMR 热载，无需刷新页面
```

注意：`link:` 不会安装本仓库自己的依赖，所以先 `pnpm install`；桌面版要求 profile 已初始化且应用已退出。

**回滚**（把插件从 profile 摘掉）：

```bash
dsh plugin --profile desktop remove dsh-panellist
```

如果卸载不干净，直接编辑 `~/.dsh/profiles/desktop/package.json`：删掉 `dependencies` 里的 `dsh-panellist` 与 `dsh.profile.bundles` 里的同名字符串，再删掉 `node_modules/dsh-panellist`。配置文件 `$DSH_HOME/panellist.json` 是唯一的外部状态，删掉它即恢复出厂。

插件被禁用或卸载时不会留下残留：注册项的 `order`/`label`/组件都会还原、分组行被释放、注入的样式表被移除、所有标记属性被清除（`src/client/registry/rail.tsx` 的 `dispose`）。

### 质量门槛

```bash
pnpm typecheck  # tsc --noEmit
pnpm test       # vitest run（jsdom）
pnpm build      # tsc（仅声明）+ tsdown（宿主半 + 浏览器半）
pnpm check      # 以上全部
```

测试覆盖三块：**模型**（序列/分组/覆盖的归一化、序列化、迁移、损坏回退）、**管理面板交互**（拖拽、上下移、图标选择、SVG 净化、导入导出）、**降级路径**（四项自检各自失败后的只读行为）。不引入对真实 DSH 界面的 E2E。

## 8. 首版范围与非目标

**首版包含**：序列编辑（拖拽 + 键盘兜底）、分组、显示/隐藏、名称与图标覆盖（原图标 / 内置图标集 / 粘贴 SVG）、配置导入导出、孤儿保留与清理、中英双语界面、自检与只读降级、README 双语 + 截图。

**首版不做**（留给 v1.1）：分组内搜索、轨道上的右键快捷菜单、多语言分别填写的名称、对真实 DSH 界面的 E2E。

**非目标**：管理右栏卡片页签；管理「设置」对话框自身的页签顺序；改动任何插件页面的内容；替代 DSH 自带的面板列表。

### 不启动应用也能做的静态校验

挂载层本身可以离线验：用 CLI 把本仓库的 patch 叠加到任意**非 desktop** profile 上，只导出组合结果（`desktop` profile 由 Electron 应用独占管理，CLI 会直接拒绝，这是刻意的）。

```bash
# 造一个临时 profile（从内置 web 模板派生），叠加本仓库的挂载层，只打印组合树
dsh panellist-dryrun --from-default-profile web \
  --patch E:/ai-code-space/dsh-panellist/cordis.patch.yml --dump-config
```

组合树里应当出现下面这两行（已实测）：

```
# == E:/ai-code-space/dsh-panellist/cordis.patch.yml
- id: panellist
  name: dsh-panellist
```

这条命令不启动任何服务、不装依赖；验证完把 `$DSH_HOME/profiles/panellist-dryrun` 删掉即可。`tests/manifest.spec.ts` 把这几个一致性断言（包名 = 插件 `name` 导出 = patch 里的 `name`、运行时读取的文件都在 `files` 里、schema 版本与路由前缀单一来源）变成了每次 `pnpm check` 都会跑的用例。
